# ScoreTurner · 自动翻谱软件

一个可以直接双击打开使用的乐谱自动翻页工具：导入 PDF / 图片乐谱 → 标记小节 → 跟着节拍器演奏 → 当前小节实时高亮 → 到点自动翻页。
**反复记号、跳房子、嵌套反复都会参与小节计数与翻页判断。**

---

## 1. 快速开始

**零门槛流程：导入 → 设 BPM → 空格 → 开始弹。** 导入后会按「每行 4 小节 × 4 行」自动标记，可以直接就播放。

| 需求 | 做法 |
|---|---|
| 打开 | 双击 `index.html`（无需安装、无需联网、无需起服务器） |
| 先体验 | 点顶栏 **示例乐谱** —— 会自动生成一份含反复 + 跳房子的 2 页合成乐谱，并带配套小节坐标 |
| 用自己的谱 | 点 **导入乐谱**，选 PDF 或若干张 JPG/PNG（多张图按文件名排序，一图一页） |
| 开始 | 设 BPM 与拍号 → 按**空格**（或点「▶ 开始」）。小节框、高亮、翻页都会自己走 |
| 网格不准 | 右侧「结构与反复」改「每行 / 共几行」→ 点 **全部页重画**（常用：3×4、4×4、6×3）。也可以直接点「**自动识别小节线**」，软件会从页面像素里真找小节线 |
| 精修 | 按 `E` 进编辑模式：拖动小节框移位、右下角把手缩放、空白处拖出新的框 |
| 标反复 | 编辑模式选中某个小节框 → 右侧「结构与反复」里勾 `|:` / `:|`、填跳房子编号（如 `1` 或 `2,3`） |

> PDF 渲染用的是 pdf.js 的「同线程假 Worker」模式：浏览器禁止从 `file://` 创建 Worker，
> 本项目把 `pdf.worker.min.js` 当普通脚本引入，pdf.js 检测到 `window.pdfjsWorker` 后会自动退回该模式，
> 代价是渲染时会短暂占用主线程（约几十毫秒），换来的是零配置即可用。

## 3. 核心模块划分

| 层 | 模块 | 职责 | 不做什么 |
|---|---|---|---|
| 数据 | `core/store` | 持有唯一状态树，patch 式合并、广播变更 | 不含业务逻辑 |
| 通信 | `core/bus` | 模块间事件：beat / position / command / page:turn | 不持有状态 |
| 算法 | `modules/structure` | 阅读顺序还原、反复/跳房子展开、边界查询 | 不碰 DOM、不碰音频 |
| 时序 | `modules/metronome` | 音频时钟、预调度发声、击拍定速 | 不知道乐句是什么 |
| 位置 | `modules/tracker` | 第几拍 ↔ 时间线第几格，含手动校正 | 不认识页面渲染 |
| 决策 | `modules/pageTurn` | 从当前格往后找第一次换页点，按提前量触发 | 不直接翻 DOM |
| 适配 | `modules/scoreLoader` | PDF/图片 → `render(i,w)→{dataUrl,w,h}` | 不关心怎么显示 |
| 识别 | `modules/barlineDetect` | 从像素里找谱线、小节线、双竖线 | 不猜音符、不做 OCR |
| 表现 | `ui/renderer` | 画图、动画、指针输入 → 结构编辑事件 | 不做业务判断 |
| 表现 | `ui/panel` | 控件 ↔ 状态双向同步 | 不跨模块直接调用 |
| 装配 | `app.js` | 订阅顺序、重算时机、command 分派、对外 API | 不实现具体算法 |

**依赖方向严格单向**：`algorithms ← state ← orchestration → ui`，任何两个功能模块之间都没有直接引用，
所以 `structure.js` 可以在 Node 里直接跑测试，`metronome.js` 可以换了实现而不动其它一行。

## 4. 关键设计一：为什么是「演奏时间线」

乐谱的**物理顺序**（页 → 行 → 小节）和**演奏顺序**（反复、跳房子、D.C./D.S. 造成的跳转）不是一回事。
真实驱动翻页的必须是后者，否则反复回头时页数会算错。

所以 `structure.buildTimeline()` 把带跳转结构的乐谱**展开成一条线性序列**：

```
timeline[i] = { seq, measureId, page, rect, firstBeat, beats, bar, pass, take, timeSig }
```

展开之后：

* 小节计数 = 在这条数组上走一格；
* 当前位置 = 二分查找当前拍落在哪一格；
* 翻页判断 = 往后找到第一个 `page` 不同的格子；
* 反复回头在时间线上只是"序号变小"，对下游完全透明。

**时间的基本单位是「拍」，且 1 拍 = 节拍器的一次点击。**
这样"提前 2 拍翻页"不需要任何时值换算——八分音符、附点音符的差异全部被拍号解析吸收掉：

```js
beatsOfTimeSig({num:6, den:8}, compound=true)  // → 2（按附点四分计）
beatsOfTimeSig({num:6, den:8}, compound=false) // → 6（按八分计）
```

个股小节的拍数也可以手动覆盖（弱起小节等），写在 `measure.beats`。

### 反复与跳房子怎么算

主干是一个带栈的游标循环，`for` 之外没有递归：

* **开始反复 `|:`** → 把当前小节下标压入 `repeatOpen`（已是 opened 则不重复压，回跳时会再次经过）
* **结束反复 `:|`** → 取栈顶作为跳回目标，按 `repeatCount` 计数；次数用完则出栈
* **跳房子** → 连续的 `volta` 小节构成一个组，组内再按编号切成员；
  每次"跳过这个组回头"就把该组的通过次数 +1，下次自动选中下一支成员，其余成员整段跳过
* **房子组自带的 `:|`** → 这类记号的 `:|` 通常画在第 1 房子的末尾那一小节上，后面几遍根本不会走到它，
  因此反复必须挂在**组**上判定，而不是那一小节（这是最容易写错的地方，`groupRepeatJump()` 专门处理）
* **D.C. / D.S.** → 小节上的 `jump:{targetIndex,times}`，与反复走同一个"回头"出口

**所有回头动作只有一个出口** `jumpBack()`，它统一做两件事：

1. 清理被重新经过区间**内部**的嵌套反复计数（否则第二次经过外层时内层不再反复）；
2. 把区间内所有跳房子组推进到"下一支"。

这两件事一旦被拆到多处调用就会出现"内层只反复一次""第二遍不换房子"的经典 bug——本项目正是靠单测把它们钉住的。

## 4.5 自动识别小节线（`modules/barlineDetect.js`）

不引第三方库、不联网、不 OCR，纯几何识别：

1. **行投影**：横向数暗像素，横跨 ≥35% 页宽的行 = 谱线（五线谱 5 条 / 六线谱 6 条；notation+tab 双谱表会被并成同一行）
2. **谱线聚类成行系统**：取**最长的一段等间距线**（房子括线、连谱号这类不等距的杂线会被剔掉）
3. **找贯穿谱表的连续竖线**：判据是**每列的最长纵向暗色游程 ≥ 谱表高度的 85%**
   —— 这一步是关键：符干+符头连起来约 33px 高，按"暗像素占比 ≥50%"会被误判成小节线，
   改成"必须整条不断"之后，假阳性直接清零
4. **相邻两条小节线之间 = 一个小节**；间距 ≤16px 的竖线并成一组 = 一条双竖线

**反复记号怎么定**：检测层只报"哪里有双竖线"，**方向不在这里猜**（1px 级别的粗线在 JPEG/抗锯齿下不稳定），
而是交给上层按顺序**两两配对**：先出现的那一处是 `│:`，后出现的那一处是 `:│`。

已验证（合成示例谱）：每页 16 个格子全部命中，反复段落（第 4→第 7 小节）被正确配对。

已知边界：**跳房子（1. 2. 3. 房子）目前不自动识别**，需要在编辑模式手动勾（软件不会乱猜它）；
扫描件/手写谱的识别率会下降，识别不出来时会自动退回网格并提示。

## 4.6 谱面印刷号对齐（`computeBarNumbers` + `pageStarts`）

**跳转 / 高亮显示的「第几小节」一律按"谱面印刷号"走，而不是软件内部的顺序号。**
这是修复"跳到 70 却落到 72"的根因：用户脑子里想的是印刷号，而识图只能给出顺序号，
两者在谱子开头有弱起、前奏、或识别少算 2 格时就会差一个常数偏移。

- 每页有一个 `pageStarts[p]` = 第 p 页第一格**谱面印着**的小节号（如弱起后第一格印着 `3` → 填 `3`）。
- `computeBarNumbers` 按"页 → 行 → 列"顺序给每格赋号：**对齐页用你填的号开头，未对齐页自动顺延上一页末号 +1**。
  —— 所以通常只需把**第一处错位的那一页**对齐一次，后面整页自动跟上。
- 对齐结果写入 `pageStarts` 并存盘（`persistence`），**重新导入同一份乐谱自动恢复**，
  且**不会被自动识别小节线冲掉**（识别只更新几何，编排号仍由 `pageStarts` 推导）。
- **数字版 PDF（含文字层）导入后自动对齐**：软件在「自动识别小节线」时会并行从 PDF 文字层
  读取每页候选数字，再用**跨页投票**求解全局起始号——若起始号是 `s0`，则第 p 页起始应为
  `s0 + 前面各页格数之和`；能被多页互相印证的 `s0` 才被采信（≥2 页），品格数字等噪声各投各的散票被自然过滤。
- 「**自动读谱面小节号**」按钮：用户主动点击 = 让软件重读，用印证结果**整体覆盖** `pageStarts`
  （包括之前填错的值）；投票解不出时回退单页启发式只补空、不覆盖，并如实提示读到多少。
  导入时的自动对齐仍是**非破坏性**的（只补空，不动手动值）。
- 用法（数字版 PDF）：导入即自动对齐；若之前填错过，点「自动读谱面小节号」一键修正。
- 用法（扫描件 / 图片谱）：无文字层时自动读取会失败并回退，此时编辑模式 →
  「本页第 1 格谱面小节号」填印刷号 → 点「对齐谱面小节号」。

> 设计取舍：项目**不做 OCR、不碰像素**，只读取 PDF 自身携带的「文字层」（数字版 PDF 导出时保留的真实文本）。
> 大多数排版软件（Finale / Sibelius / MuseScore / Dorico / 制谱软件打印的 PDF）都带文字层，小节号能被稳定读出；
> 扫描件 / 图片谱没有文字层，读取返回 `null`，此时回退到手动「对齐谱面小节号」——绝不瞎填，
> 宁可让用户手填，也不把整首曲子的编号带偏。

## 5. 关键设计二：状态管理

```
                 ┌──────────────┐
   输入事件  ──▶ │  command     │──▶ app.js 命令表 ──▶ 调用各模块公开 API
   (键/踏板/UI)  └──────────────┘                            │
                                                            ▼
   score.measures ─┐                                  store.set(patch)
   timeSig ────────┼──▶ recompute() ──▶ timeline ──▶ 订阅者重绘 / 重算翻页
   repeat 策略 ────┘                                        │
                                                            ▼
   metronome ──beat──▶ tracker ──position──▶ renderer / pageTurn / panel
```

### 状态分片（`js/core/store.js`）

| 分片 | 内容 | 谁来写 |
|---|---|---|
| `score` | 页、小节矩形、反复/跳房子标记、`rev` | 编辑交互 & 导入 |
| `timeline` | **派生**：展开后的演奏序列 + 总拍数 | 仅 `recompute()` |
| `transport` | playing / bpm / timeSig / beat / tlIndex | tracker、面板 |
| `view` | 当前页、双页、缩放、深色、全屏、`autoTurnPending` | renderer、命令 |
| `turn` | 自动开关、提前量、单位、动画时长、`lastTurnKey` | 面板、pageTurn |
| `edit` | 模式（play/edit）、选中小节 | 命令 |
| `audio` | 音量、重音、细分 | 面板 |
| `repeat` | 默认反复次数、最大通过数 | 面板 |
| `input` | 踏板/快捷键绑定 | input 模块 |

### 更新语义

* `store.set(patch)` 顶层 key 替换、对象 slice **浅合并**、数组整体替换 → 写 `store.set({transport:{bpm:120}})` 即可局部更新。
* 订阅回调拿到 `(state, changedKeys)`，**据此决定要不要重算派生数据**：只有编排层涉及的 key 变化才触发 `recompute()`；
  拖拽小节这种高频操作若只改坐标则不重算时间线（见 `patchHasStructure()`），避免拖动时 O(n) 重排。
* 不存在"两个模块同时改同一份状态"的路径：视觉状态全部由 store 单向流向 renderer/panel。

### 为什么订阅顺序重要

```
metronome ──'beat'──▶ tracker ──'position'──▶ renderer / pageTurn / panel
```

`app.js` 里 `bus.on('beat')` 必须早于 `bus.on('position')` 注册，
否则翻页会拿着"上一拍"的位置做决策。这条顺序要求在 `app.js` 头部注释里被显式写死说明。

## 6. 关键设计三：翻页与"提前翻页"的去冲突

```js
plan() {
  找到 j > 当前格 且 timeline[j].page ≠ 当前页 的第一个 j;
  triggerBeat = timeline[j].firstBeat − 提前量;   // 提前量单位可为拍/小节，负值 = 延后
}
```

* 每拍调用一次；用 `lastTurnKey = 当前格 → 边界格` 去重，保证一个边界只翻一次；
* 手动跳转后会 `invalidate()` 清标记，回到同一处边界可再次触发；
* 因为只看时间线，回头反复时会自然算出"翻回上一页"，**不需要为反向翻页写任何额外逻辑**。

**踩坑点（已修复并写进测试）**：提前翻页后，当前小节其实还停留在上一页；
此时若在 `position` 里无脑「保证当前页可见」，会立刻把刚翻过去的页面拉回来，表现成"翻页总是迟到"。
解决办法是引入 `view.autoTurnPending`：**自动提前翻页后进入一段窗口期**，
期间不纠正视野，直到演奏真的走到目标页为止；手动跳转（点击小节、踏板、方向键）则允许无视窗口立即跟随。

## 7. 演奏场景优化

| 能力 | 实现 |
|---|---|
| 快捷键 | 空格播放/暂停、`←→` 前后小节、`Ctrl+←→` / `PageUp·PageDown` 翻页、`R` 重置、`M` 静音开/关、`F` 全屏、`B` 深色、`A` 自动翻页、`E` 编辑模式、`D` 小节框、`Tab` 收面板、`+/-` 微调 BPM |

| MIDI 踏板 | 「接入 MIDI 踏板」按钮 → Web MIDI，默认识别 CC64/66/67（延音等踏板控制器） |

| 屏幕常亮 | Wake Lock API（`file://` 属安全上下文，Chrome/Edge 可用） |
| 深色 | 顶栏「深色」按钮，配色走 CSS 变量，全站切换 |
| 视线干扰最小 | 舞台区只有乐谱 + 底部一个细条形状态，顶栏可用 `Tab` 收起，节拍指示器常驻但不抢视线 |
| 静音 | 顶栏「声音」按钮 / `M` 键：只掐掉发声，顶部拍点与小节高亮照常同步（静音不打断视觉） |
| 拍点指示 | 顶部圆点 = 当前小节第几拍，第 1 拍用重音色，点数随拍号自动收窄（3/4 只显示 3 个） |

## 9. 已知边界

* **小节必须人工校准**：从像素里自动识别小节线属于乐谱 OMR 领域，本项目不做。
  做法是「导入即按 4×4 自动铺一层网格」兜底，让你先能跑起来，再用面板改「每行 / 共几行」一键重画，
  或在编辑模式拖框精修——通常一页十几秒就能校准完。校准只影响高亮位置和翻页时机，不影响能否播放。
* 每个反复段落的演奏次数写在 `:|` 那一小节的 `repeatCount`（默认取全局 `repeat.defaultCount`）。
* 支持 D.C./D.S. 的「跳回来几遍」，但 `al Coda` / `Fine` 这类需要额外符号落点的高级跳转尚未提供 UI，
  数据层已预留 `measure.jump`，手写 JSON 可用。
* 本地存储只存**结构**（小节坐标与标记），不存乐谱像素，因此不会撑爆 localStorage；
  再次导入同一份文件时按 `文件名+大小+修改时间` 指纹自动恢复标记。
